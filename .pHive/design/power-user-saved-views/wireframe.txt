Wireframe — Saved Views panel (within /mapstack/advanced's left sidebar)
Rendition 1 — ASCII fallback (Frame0 CLI not installed on this machine)
Reuses allergy-locator's ProfileCompare.tsx checkbox-list interaction shape
(reviewed during design-discussion open question 4), adapted for save/restore
rather than compare-on-map.

+-------------------------------+
| LAYER PICKER (see             |
| power-user-comparison-table   |
| topic for this section)       |
| ...                            |
+-------------------------------+
| SAVED VIEWS                    |
|                                 |
| [Save current view...]  (btn)  |
|                                 |
| * Grass + Violent Crime         |
|     [Restore] [Rename] [Delete] |
| * Weekend house-hunting shortlist|
|     [Restore] [Rename] [Delete] |
|                                 |
| (empty state, 0 saved views:)   |
|  "No saved views yet. Select    |
|   layers above, then Save       |
|   current view to keep them."   |
+-------------------------------+

"Save current view..." click -> inline text input (name) + Save/Cancel,
matches a lightweight inline-rename pattern rather than a modal (no modal
precedent exists anywhere in mapstack-us's current UI).

Restore click -> updates LayerPicker selections + ComparisonTable sort +
the shared city/year URL params (pu-3) to match the saved view, in one action.

Delete click -> browser-native confirm() is acceptable for v1 (matches the
project's "no boilerplate" developer preference) rather than a custom
confirmation dialog.
